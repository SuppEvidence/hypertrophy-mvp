# Manual weekly coach planning patch

Apply this overlay on top of the current T0–T3 app and the prior workout-continuity/exercise-memory update. The ZIP contains full replacement files at project-relative paths and two additive database migrations. It contains no `.env.local` and requires no new environment variable. Your existing `OPENAI_API_KEY` and T3 model configuration are used; optional `OPENAI_WEEKLY_REASONING_EFFORT` overrides the weekly coach's default `high` effort.

## Behavior

- Open **Plan → Weekly coach** on Monday, before or after completing workouts that week. Completed sessions are credited and fixed; mark only the remaining dates and minutes available, then add relevant constraints. The coach reads mesocycle priorities, the program's template frameworks, recent performance and workout analyses, measurements, energy phase, and exercise contribution estimates. It proposes dated remaining workouts including physical sets, set types, exercise choices and a week-level effective-dose summary that includes already completed sets. Templates can recur, be reorganized, and gain compatible catalog exercises.
- Review the proposal and explicitly approve it. Approval saves the actual dated occurrences. Opening an occurrence from the weekly plan or logger passes its approved exercise and set choices into the ordinary workout start and T2 daily review. Remembered exercise choices cannot silently replace an approved weekly choice. T2 daily proposals still require their usual approval; T1 per-set adjustment is unchanged.
- Mark a remaining occurrence missed from **Plan → Weekly coach**. A deterministic allocator spreads its sets among the remaining unstarted sessions by movement pattern, within exercise, session and time limits. It can carry an exercise as a temporary slot when no matching slot remains. Completed/started workouts never change. Unplaceable sets are shown; no coach review runs. Original templates remain untouched. With an approved week, the old template-level missed-workout form is replaced by a link to the weekly plan.
- Proposals are validated for available dates, template and exercise IDs, movement compatibility, individual set types and safe retention of existing intensified sets, and plausible exercise/session capacity. A proposed change to the next week can run on the next Monday; this patch plans the **current** Monday–Sunday week and does not schedule a future week in advance.

## Development

1. Extract the ZIP into the app's project root, overwriting matching files. Preserve all paths in the archive.
2. Connect `.env.local` to your **development** database and run `npx prisma migrate deploy` **before** starting the app. This applies both `prisma/migrations/20260928100000_weekly_coach_plans/migration.sql` (new `weekly_coach_plans` table) and `prisma/migrations/20260928103000_weekly_coach_completed_baseline/migration.sql` (completed-session snapshot). Run `npx prisma generate` if your existing setup did not generate a client automatically.
3. Run `npm run typecheck`, `node --import tsx scripts/test-weekly-coach.ts`, and `node --import tsx scripts/test-coaching-models.ts`.
4. Run `npm run dev`. With Monday already completed, create a weekly proposal for later dates. Verify Monday is credited in the dose summary and cannot be selected again. Check remaining dates/exercises/set types, approve, open a scheduled workout, and confirm its logger and daily coach show the approved exercise. Mark a second unstarted occurrence missed and check remaining workouts and the unallocated set count. Test a recurring template on two different dates.

## Production

1. Apply both included migrations to the **production database before deploying the code**: run `npx prisma migrate deploy` through your existing secure production migration method, with `DATABASE_URL` sourced from production. Do not accidentally run it against your development `.env.local`; merely pushing to Vercel does not execute this migration unless your deployment pipeline explicitly does so.
2. Commit the patched files and push to the production branch (`main` in your existing workflow). Let Vercel build and deploy. No secret needs to be changed for this patch.
3. This week, with Monday already completed, open **Plan → Weekly coach**, select only upcoming workout dates, review how Monday counts toward the effective weekly dose, approve the proposal, and open one dated occurrence in the logger. Confirm that marking a different planned occurrence missed updates only the remaining unstarted workouts. The planner may be run after completed uncoached workouts, but it cannot revise a workout that was already started from an approved weekly plan; use **Mark missed** for later availability changes. Draft workouts must be finished before planning. The app uses the Europe/Helsinki calendar for week boundaries.

Verified locally with Prisma Client generation, TypeScript typecheck, production boundary verification, deterministic weekly and model routing tests, targeted ESLint, and whitespace checks. Live OpenAI behavior and production database migrations cannot be tested from this workspace; invalid model plans fail validation and are shown as an error without being saved.
